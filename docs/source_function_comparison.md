# 真实 DTM：同一高程函数的矢量表达收益

入口：`/compare#source-function-results`。对比页现在以方向精度、真实源函数文件收益和原生查询效率为三条主线；既有函数、高阶控制、论文复现与不利结果继续保留，历史深链接可自动展开相应内容。

## 已验证的结果

十城二十个预先固定的真实 1 m DTM 样区，每区使用全部 65 × 65 原始 Float32 高程节点，比较像素中心之间的 64 × 64 m。以逐格双线性插值为相同参考函数：

| 完整表示 | 每样区实际字节数 | 源函数一致性 |
| --- | ---: | --- |
| GUGIS 原生直纹面带 | 135,528 | 通过 |
| 同节点 P1 三角带 | 135,528 | 单元内部存在高程差 |
| 逐格共享节点 P2 三角函数 | 694,376 | 通过 |
| 隐式 XY Float32 规则高程格 | 16,980 | 通过 |

面带相对本次逐格 P2 矢量表示，完整文件减少 **80.5%**。二十样区合计节省 11,176,960 B。面带和 P2 全域 E₂ 均低于 10⁻⁸ m²；这表示相对同一源插值函数的一致性，不表示独立实测地面精度。P1 相对源函数的全域 RMS 差为 1.062–13.696 mm。

规则高程格和实际无损 GeoTIFF 在这些规则样区中更小，页面直接展示。结果不能推广为优于全部栅格、全部高阶三角方法或最优编码。文件字节数不是运行内存，也不是 ArcGIS 软件性能。

## 可以直接演示

1. 选择固定样区，查看完整文件柱状图与全域差值。
2. 点击“验证实际高程与精细函数结构”，校验并载入三个真实矢量二进制文件和原始 Float32 源高程格。
3. 默认定位 P1 最大高程差；移动 X/Y 滑块，同点读取 BNG 坐标、高程、相对源函数差值和坡度。三个函数的 1 m 源单元立体采样使用同一垂直比例，并明确标注。
4. 下载当前原始像素 GeoTIFF、GUGIS 面带、全部结果 CSV 或完整证据 ZIP。

## 实现与复核

新增 GPR4 研究格式包含共同的 80 B BNG/ODN/米制坐标头部、Float64 XYZ 节点池和原生面记录。64 条面带共享 4,225 个源节点；逐格 P2 采用 16,641 个共享节点、8,192 个二次三角形。面带的执行缓存使用连续函数系数，不以三角网替代原生函数；缓存成本不计入文件收益，也没有作运行内存测量。

全部 80 种表示执行 993,360 次内部和源节点查询，核验高程、梯度、BNG 坐标、越界拒绝、二进制往返及 P1 最大差值见证点。独立五阶求积复核整个覆盖域；Float64 数值余量不是区间算术证明。代码、源数据、全量记录和 ZIP 均绑定 SHA-256。

输入来自英国环境署 EA 2022 1 m 裸地 DTM，许可 OGL v3。保留 WCS 单位字段与官方米制正文的冲突警告，ODN/米来自源数据集说明。可下载 GeoTIFF 保留原 Float32 像素、EPSG:27700、1 m 分辨率和无损压缩；其像素面积覆盖 65 × 65 m，函数比较覆盖像素中心之间的 64 × 64 m。

这些分段 DTM 不满足论文严格凸 C² 曲面的全部前提。本节 P1 是源规则节点三角化，不是论文式贪心细化。先前按自适应 P1 文件预算进行的真实 DTM 控制试验中，规则面带没有取得优势，负面结果保留在查询结果的控制试验中。

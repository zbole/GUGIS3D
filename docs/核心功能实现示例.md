# GUGIS3D 核心功能实现示例

本文面向需要审查模型方法和复现结果的地理科学研究者。所有示例对应当前代码和布里斯托起始街区项目，演示脚本只读取正式城市文件，不修改其内容。

## 运行一条可复现的分析链

在仓库根目录安装好项目依赖并启动本地项目后，运行：

```powershell
cd frontend
node scripts/demo-core-functions.mjs
```

脚本读取 `../.local/city/current.gugis.json`，调用实际的 City 1.2 解码器、原生地形分析器、联合空间查询和模型交线算法。当前保存版本运行所得的关键结果如下；项目编辑后数字会随数据变化：

```json
{
  "city": {"buildings": 616, "models": 606, "roads": 544},
  "terrain": {"nativePatches": 2184,
              "hit": {"patch": "p1060", "kind": "ruled-strip", "height": 20.73}},
  "analysis": {"routeMetres": 107.7, "terrainCoverage": 1,
               "corridorMetres": 30, "selectedObjects": 7,
               "modelIntersectionSegments": 43},
  "inMemoryRoundTrip": {"buildingsPreserved": true,
                        "terrainPatchesPreserved": true,
                        "functionComponentsPreserved": true}
}
```

上面的 `height` 属于该合成地形声明的 `local` 高程基准，并非布里斯托的实测海拔。交线段数依赖当前模型和路线，不是固定性能指标。

## 示例一 共享建筑定义与可恢复的城市实例

City 1.2 档案把几何、建筑定义和实际落点分开。`geometry_library` 保存共享几何；`assets` 保留模型模板与构件语义；`instances` 引用模型并记录每栋的经纬度、朝向及名称。这样复制建筑时可以复用定义；修改单栋时可以通过新的资产引用保护其他实例。

以下是字段关系示意，省略了完整楼栋的数千个节点，不能直接当作完整城市文件导入：

```json
{
  "format": "gugis-city",
  "version": "1.2",
  "geometry_library": {"g0": {"kind": "box"}},
  "assets": {"example-house": {
    "templates": {"wall": {"geometry": "g0", "size": [4, 0.25, 3], "color": "#d0b89a"}},
    "nodes": [{"id": "floor-1", "category": "floor"},
              {"id": "wall-1", "parent": "floor-1", "category": "wall",
               "template": "wall", "position": [0, 0, 1.5]}]
  }},
  "instances": [{"id": "house-1", "asset": "example-house",
                 "longitude": -2.603, "latitude": 51.454,
                 "altitude": 0, "heading": 0}]
}
```

实际完整文档由 `frontend/src/studio/cityArchive.ts` 的 `encodeCity` / `decodeCity` 转换。离线示例通过 `decodeCity(encodeCity(city))` 核查建筑数、原生地形片和函数构件仍在；正式保存则由 `backend/app/routers/city.py` 校验 `base_revision`，保留前后快照并原子替换当前文件。示例脚本不发送保存请求。

## 示例二 函数组合生成可编辑的城市地物

当前圆形广场实例引用共享的 `round-plaza` 定义。铺装、路缘和中心圆盘分别保存函数及参数，而不是把临时渲染三角形当作档案主体：

```json
{
  "asset": "round-plaza",
  "components": [
    {"category": "铺装", "function": "cylinder",
     "parameters": {"radius": 12, "height": 0.18}},
    {"category": "环形路缘", "function": "annular-prism",
     "parameters": {"inner_radius": 12, "outer_radius": 12.45,
                    "angle": 360, "height": 0.28}},
    {"category": "中心圆盘", "function": "cylinder",
     "parameters": {"radius": 2.2, "height": 0.25}}
  ]
}
```

完整记录还含每个构件的 `id`、局部位置和颜色，以及实例的地理坐标、朝向、比例与地上/地下分类。`frontend/src/studio/environment.ts` 的 `functionSolid` 在显示时将球、圆柱、圆环体、拱形体或盒体离散成闭合三角面；档案仍保留函数名称和参数。界面允许选择是否同步更新同定义的多个实例，保存前预览影响范围，保存后可借助版本历史恢复。

## 示例三 用两条边界曲线表达原生直纹面带

对相邻的左右边界点 `a=Lᵢ`、`b=Rᵢ`、`c=Lᵢ₊₁`、`d=Rᵢ₊₁`，项目采用：

```text
L(u) = (1-u)a + uc
R(u) = (1-u)b + ud
S(u,v) = (1-v)L(u) + vR(u),  u,v ∈ [0,1]
```

固定 `u` 时，`v` 方向是一条直纹；连续区段共享控制点。对应实现为 `frontend/src/studio/terrainMath.ts` 的 `ruledPoint`。地形档案仅保存共享点数组和每片 `{id, kind:"ruled-strip", left:[...], right:[...]}`。起伏较大的局部还可用三角带或三角扇。原生查询先定位面片，再反求局部参数和高程、坡度；WebGL 使用的显示网格不替代原生求值。NoData 返回未命中，不能外推为已有地面。

导入真实 DTM 时，可在网站“地形 / 地物”选择单波段 `.tif` 或 `.asc`。服务端 `POST /city/terrain/import` 接收文件、文件名、坐标系、高程基准和采样步长，裁剪至当前研究范围，返回待确认的地形对象。当前档案的文件名明确含“合成DEM_非实测”，其 `vertical_datum` 为 `local`；不能据此声称测绘精度或 ODN 高程。

## 示例四 从点位查询走到联合剖面

演示脚本执行的关键调用如下；路线仅用于演示，距市政测绘流程还需真实数据核验：

```ts
const point = { longitude: plaza.longitude, latitude: plaza.latitude, altitude: 0 };
const query = queryCityPoint(city, point, 100,
  { id: plaza.id, layer: plaza.layer });

const profile = analyzePath(route, city.environment.terrain);
const corridor = analyzeCitySection(city, route, profile, 30);
const trace = traceCityObject(city, route, plaza.id);
```

`queryCityPoint` 返回命中的原生面片、源高程、坡度、邻近建筑/地物和道路。`analyzePath` 使用原生面带/三角形求高程并保留缺测断点。`analyzeCitySection` 以 30 米剖面带筛选模型包络、地上地下对象和地下模型的保守竖向间距。`traceCityObject` 则只对所选对象计算其已存储三角面与中心竖直平面的有限交线；函数曲面采用当前显示细分精度。

剖面带命中不等于中心平面已经穿过实体，页面分别显示包络矩形和交线。地下包络重叠只提示需要进一步核验，不构成施工级碰撞判定。若源地形缺测，源高程和埋深保持未知。相关实现分别位于 `spatialAnalysis.ts`、`terrainAnalysis.ts` 与 `sectionTrace.ts`。

## 示例五 保存、复算与边界检查

路线的点、采样间距、剖面带宽度、来源和算法版本保存在城市元数据中，重新打开时依据当前地形和城市对象复算，而不是沿用旧对象数量。项目修改与正式保存走同一版本冲突保护；未经确认的建筑或地物草稿不会写入正式城市。

```powershell
# 只读检查服务，不提交任何修改
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/city/current |
  Select-Object revision, storage
```

所有结果都应附带源数据和精度条件。当前项目包含约 600 个 OSM 建筑轮廓、3 个形态参考地标与英式住宅设计示范；立面、层高和室内多数是规则推演。真实规划判断还需要授权 DTM、权威建筑/地下资料、现场核验及与现有 GIS 在同精度、同硬件下的评估。

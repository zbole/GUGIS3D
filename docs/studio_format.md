# GUGIS Studio 对象格式 1.2（兼容读取 1.0 / 1.1）

本格式是该项目新增的自包含三维对象交换格式，不代表原 C++ 二进制 GUGIS 标准。

顶层必须包含 format=gugis-studio、version=1.0 / 1.1 / 1.2、coordinate_system=ENU_METERS_WGS84、parameters、templates、nodes。完整 JSON Schema 可由 GET /studio/schema 获取。

parameters 包含名称、建筑样式、scale 比例、层数、单元数、层高、经度、纬度、基准高程和朝向。局部位置单位为米；地理原点为 WGS84，经纬度用度，高程按椭球基准解释。heading 为绕局部天轴的顺时针旋转角度，零度时 x 向东、y 向北、z 向天。模板位置是楼栋坐标系内的绝对局部坐标；parent 表达语义归属，不叠加父节点位移。

templates 存放复用实体。box 使用三个正尺寸，以原点为中心；mesh 使用显式 XYZ 顶点与向外定向的三角面索引。坡屋顶由闭合三角面实体描述，不由二维轮廓简单拉伸得到。每个实例通过 template 引用实体，通过 position 放置。

1.2 增加可选的构件 `rotation_z`（度，绕局部 Z 轴逆时针，默认 0）。变换顺序为：模板顶点先局部旋转，再加 position，最后应用建筑实例的 ENU 定位与顺时针 heading。分组不允许旋转，父节点不叠加变换。此定义也用于相机包围盒与拾取。1.2 可带 `overview` 简模字典，最多 8 个闭合实体，坐标已经位于楼栋局部坐标系；1.0 / 1.1 禁止携带这些新能力。

nodes 按父节点在前的顺序排列。building → unit → floor → dwelling / room → 构件形成语义层次。楼板、楼梯、屋顶直接归属楼层。构件继承楼层与单元编号，旧住宅窗户、门、阳台可追溯至 dwelling 的演示住户编号；英式住宅与公共地标使用 room，不虚构真实住户。1.1 增加 room、column、ornament 类别以及五类英式样式。所有住户信息均为合成示例。

校验拒绝重复编号、缺失父节点、循环/乱序、缺失模板、错误语义父类、不一致的单元或楼层、非有限数值、越界面索引、退化三角面、未闭合或方向不一致的三角面实体。闭合三角面校验并不替代完整 CAD 拓扑与自交检测。

限制：单栋上传不超过 8 MiB；层数 1–30、单元数 1–4、参数层高 2.5–4.5 m；最多 12,000 个语义节点。1.0 / 1.1 最多 256 个模板及 20,000 个渲染面/盒；1.2 最多 1,024 个模板及 120,000 个渲染面/盒。轮廓细化可能按原高度推演实际层高，属性中保留标高及依据。英式住宅样式最多 12 层；地标使用参数分段而非实测楼层。城市容器与批量渲染见 city_format.md。

## 接口

| 方法与路径 | 用途 |
|---|---|
| GET /studio/example | 默认楼栋对象文件 |
| POST /studio/generate | 参数制作，返回完整对象 |
| POST /studio/validate | 校验导入对象，返回标准化对象与统计 |
| POST /studio/save | 校验并写入项目 .local/exports，返回保存位置 |
| GET /studio/files/{sha256} | 已保存文件的下载副本 |
| GET /studio/schema | 当前版本 JSON Schema |

生成、导入与保存共享后端校验。显示筛选、透明度与楼层抬升保存在前端视图状态中，不更改对象数据。渲染 ID 和语义 ID 分开；详查按楼层批量绘制并保留每个构件的颜色、显隐与拾取属性，避免逐面实体的开销。

文件大小按未压缩 UTF-8 JSON 字节计算。“模板复用节省”对比同一对象数据中每个构件重复写入完整模板几何的展开版本，仅衡量模板复用收益，不与未知旧文件、glTF 或压缩格式比较。浏览器 JSON 对整数的序列化与 Python 浮点序列化略有差异，界面估算与服务端实际文件大小会有小幅差异；保存回执给出实际字节大小。

# 全局优化与验收 · 2026-09-15

## 保存与恢复

- 确认草稿改用 `POST /city/draft/commit`，只发送 64 字符草稿版本令牌，直接提交服务器已有数据，省去原先重复上传整份约 32 MiB 城市的请求。
- 正式城市和草稿分别校验版本。先保留新旧快照，再原子替换正式文件；提交回执允许丢失 HTTP 响应后重试，避免重复添加。磁盘上的多个文件并非数据库事务，通过回执和文件哈希识别中断发生在哪一步。
- 刷新恢复单栋制作参数、更新模式和目标编号；再次生成沿用同一实例。导入/街区/恢复草稿不会被单栋表单意外替换。
- 草稿异常单独报错，仍能读取正式城市。损坏文件保留，禁止直接用新草稿覆盖。
- 大型 JSON 校验和城市保存放到工作线程，减少对异步请求处理的阻塞。

## 场景和界面

- 城市、楼栋详查增加“放大场景”，Esc 或工具栏按钮恢复面板；切换工作区时恢复面板。
- 压缩低高度桌面屏幕的标题/统计留白。修复地形和函数长面板溢出页面：桌面独立滚动，窄屏纵向展示。
- 函数页初次载入选中一个已保存地物，显示真实引用数量；路灯示例显示 4 个组件、2 类函数、4 个实例引用。
- 草稿预览同时比较建筑、地形控制点、地物和道路数量。整理地形提示与远景提示位置，避免重叠；选中地标仅显示一个主标签。
- 同一建筑模板的本地几何和边界顶点在构建批次中只计算一次。Cesium 在实例变换前克隆输入几何，位置与配色保持独立；此项不能理解为显存中已经实现所有构件 GPU 实例化。

## 地形性能

当前城市地形有 4,464 个控制点。固定随机种子采样 20,000 个位置，7 轮计时取中位数：查询 65.91 ms → 22.47 ms，约 2.93 倍速度。新增包围范围筛选减少无关面带的逆解计算，仍直接查询原生曲面；20,000 个查询结果逐项相等。

临时显示网格按原生点编号和边编号共享顶点，三角形数与每个三角形的空间坐标保持一致。不按四舍五入坐标合并，避免连接独立拓扑和 NoData 缺口；共享法线会使连续地形接缝更平滑。原生 GUGIS 控制点、面带拓扑和函数参数未改动。

|---|---:|---:|---:|
| 直纹面带 | 37,107 | 16,853 | 32,984 |
| 三角带 | 840 | 200 | 280 |

位置 Float64×3、法线 Float32×3、三角索引 Uint32×3 的缓冲数据合计 1,781,580 → 1,018,452 字节，减少 **42.83%**。这是同等显示精度下的地形几何缓冲容量，不是整城内存、浏览器总内存或相对点线建模的节省比例；网站原有点线内存对比仍单独保留，并正确标识旧测量是否匹配当前城市。

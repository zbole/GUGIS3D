# 函数结构的收益：与通用高阶三角插值直接对照

2026-10-06。入口：`http://127.0.0.1:5173/compare#order-structure-results`。

本轮进一步区分「近似阶数更高」与「利用直纹结构减少表达成本」。原来的 98.3% 误差收益对应论文式**线性 P₁** 插值；这里增加 P₂ 与 P₃ 控制，不能把该结果推广到所有高阶方法。

## 可以展示的结构收益

对预先定义的两个直纹结构曲面，GUGIS 二次边界直纹函数与通用高阶三角函数都能表示源多项式。保存模型的全域 E₂ 均低于 10⁻⁸ m²，这一门槛仅用于判定 Float64 数值零误差，不代表实际地面测量精度。

| 结构示例 | 三角函数空间 | GUGIS / 三角节点 | GUGIS / 三角完整 JSON | GUGIS / 三角完整 GOC2 | GOC2 实际文件减少 |
|---|---|---:|---:|---:|---:|
| 二次轮廓沿直线延展 | 完整 P₂ | 6 / 9 | 268 / 382 B | 196 / 304 B | 35.5% |
| 二次轮廓随母线线性变化 | 完整 P₃ | 6 / 16 | 268 / 901 B | 196 / 504 B | 61.1% |

JSON 分别减少 29.8%、70.3%。二进制结果避免只用十进制文本位数解释优势，包含完整头、坐标与连接关系的实际字节。不是仅凭节点数量估计，也不是测得的 RAM / GPU 内存。

两条曲线各需三个 Bézier 控制点，共六个。覆盖同一正方域的两个 P₂ 三角面各六个 Lagrange 节点，公共边三点共享后为九个；两个 P₃ 三角面各十个节点，公共边四点共享后为十六个。三分点先用规范有理构造，再转为 Float64，防止浮点运算方向差导致重复节点。

这是**当前两种完整研究编码的比较**，不是信息论最小码长证明；采用稀疏多项式系数、共享全局函数或其他专用编码的基线可能进一步减小文件。

## 为什么没有再次利用阶数差

局部米坐标域为 [-50,50]²，源函数明确给出：

- 示例一：`f(x,y)=30+0.002x²+0.03y`，总次数为二，使用完整 P₂ 三角空间。
- 示例二：`f(x,y)=30+0.00002x²(y+60)+0.01y`，总次数为三，使用完整 P₃ 三角空间。

GUGIS 保留 `R(u,v)=(1-v)B₀(u)+vB₁(u)` 的 P₂×P₁ 结构。第二个例子中的 x²y 项也在完整 P₃ 空间中，因此没有拿三次曲面去要求二次三角插值达到精确结果。

两种源函数均为专门定义的结构示例，不是前三个严格凸曲面，也不是实际城市 DEM。它们不属于论文严格凸场景的渐近最优证明范围，不支持推翻该定理。

研究背景：[Mirebeau & Cohen 论文](https://arxiv.org/html/1101.1452v1)介绍一般阶数的分片多项式策略，其主要严格分析针对分片线性近似。本项目的 P₂ / P₃ 文件与数值由本机生成，不是论文作者原始跑分，也不是 ArcGIS 的高阶曲面软件实测。

## 更强控制同时公开

对原来三个严格凸曲面的冻结 P₁ 网格，保留全部有向三角形和网格预算，只将插值改成 P₂。与原 GUGIS 有限候选池按 P₂ 文件预算进行选择，**27 / 27 档 P₂ 的全域 E₂ 更低**。

两类二次源曲面在 P₂ 中达到数值零误差。变曲率源在 N=2,048 的保存 P₂ 模型上 E₂ 为 0.005239384 m²。页面提供全部九档表、27 对 CSV 和三曲面科学图，数值零误差在对数图上明确按 10⁻⁸ m² 的显示下限绘制，原记录保留真实 Float64 数值。

这是阶数敏感性控制：P₂ 没有重优化选区／选边，GUGIS 也没有扩展原有限候选池。它不能证明任意网格、任意高阶方法的全局胜负；与原 P₁ 结果及两组结构编码收益分开判断。

## 编码、查询与数值核验

GOC2 二进制协议：

| 内容 | 完整表示 |
|---|---|
| 公共头 | 4 B `GOC2` + Uint32 version=2 + Uint32 控制点数 + Uint32 面片数，共 16 B |
| 控制点 | 所有 XYZ，各为 little-endian Float64 |
| 面片头 | Uint32 类型、Uint32 阶数、Uint32 节点数，共 12 B / 面片 |
| 连接关系 | little-endian Uint32 索引 |
| 类型 1 | 两条二次边界，依次存左三点、右三点 |
| 类型 2 | 完整二次／三次 Lagrange 三角节点，重心节点按 (a,b,p-a-b)，a 降序、随后 b 降序排列 |

边界曲线中间点是形状控制点；Lagrange 节点是源高程插值点，两者不能混为源测量点。

原生 TypeScript 解码器核查长度、类型、节点位置、容量及退化面，再计算高程与解析导数。网站先验证 SHA-256 和实际读取长度再解码，关闭演示取消读取；初始页面没有模型请求和 WebGL 画布。

全部 **86 组 JSON / 二进制模型**在 **352,256 个固定模型—查询点组合**上核验，两种编码的查询结果完全一致。两组结构示例还对照解析高程与导数，二次场也对照解析导数。抽查最大值没有充当连续 E∞。

完整 E₂ 由足阶求积计算；独立研究测试用单项式 Vandermonde 插值和 11×11 Gauss 求积复核全部 27 个 P₂ 保存模型，避免只重复 Lagrange 基函数实现。另核验节点 Kronecker 性、分割统一性和总次数以内多项式的再现。

公开档案：`frontend/public/research/order-controls-v1/`；摘要：`shared/terrain-order-control-v1.json`。五个 ZIP 分别对应三个高阶控制曲面和两个结构示例，每包包含当前曲面的所有原生 JSON / 二进制、独立案例记录及协议说明；全体结果和查询回执在目录根部。

复现使用新目录：

```powershell

node frontend/scripts/audit-terrain-order-control.mjs .local/research/order-control-recompute
```

# City 1.1 全城共享几何

目标是减少重复存储并保留完整城市结构。615 个建筑实例仍使用 605 套楼栋模型；不同轮廓、定位、构件归属和内部布局保持独立。相同构件几何可跨楼栋共享，颜色和尺寸参数独立保存。

## 数据结构

顶层 `format` 为 `gugis-city`，`version` 为 `1.1`。其余城市字段与 1.0 相同，新增 `geometry_library`。资产的参数与完整 `nodes` 保留；`templates` 和可选 `overview` 中的实体改为绑定对象。例如：

```json
{
  "geometry": "g_content_hash",
  "color": "#d8b58d",
  "size": [3.6, 0.24, 2.8]
}
```

`geometry` 必须指向同一文件几何库中的合法 ID；`color` 独立属于局部模板。`size` 仅允许且必须用于 `box` 原型，三个尺寸均须为正。节点仍通过原来的 `template` 引用资产内模板，节点编号、层级、位置、局部旋转、空间归属和来源属性保留。

| 原型 kind | 数据 | 还原方式 |
|---|---|---|
| `box` | 仅 `kind` | 单位盒，绑定的 `size` 指定原尺寸，局部原点在中心 |
| `box-set` | `bounds` 数组 | 每项 `[xmin,ymin,zmin,xmax,ymax,zmax]` 是一个盒体的原始极值 |
| `mesh` | `vertices` 与 `triangles` | 保留原始网格顶点和闭合三角面索引 |

组合盒体的角点顺序和 12 个三角面顺序由 [box-topology.json](../shared/box-topology.json) 定义。各盒体依次追加 8 个角点，面索引增加 `8 × 盒体序号`。只有坐标、角点顺序及三角面索引完全匹配时才转换；斜面、凹形楼板和不规则屋顶保留显式网格。不会用包围盒近似复杂形体，也不舍入坐标。常规 JSON 序列化可将负零规范化为零，空间位置相同。

几何内容以固定编码计算 SHA-256，持久 ID 使用 `g` 加前 20 位十六进制字符；短 ID 碰撞会拒绝写入。导入允许其他合法 ID，保存时按内容重新去重并清除无绑定几何。最多 50,000 条原型，单个组合盒体最多 32 个盒子。仍校验坐标范围、闭合性、三角面方向、非退化、正体积、全部引用和语义关系。

## 编辑与兼容

浏览器在 API 边界展开共享文件，编辑器继续处理完整楼栋对象。网格数组共享以减少重复分配，渲染不修改源数组；编辑通过新资产和新数据完成，保存时重新建立几何库。修改某栋不会传播到其他共享建筑。

- City 1.0 文件可直接导入，保存后升级为 1.1；旧文件自动进入历史快照。
- 整城文件自包含，无需联网或重新生成才能还原。
- 单栋导出展开全部绑定，仍是自包含的 Studio 1.0 / 1.1 / 1.2 文件。不能直接截取 City 1.1 中的资产条目当成单栋文件。
- 旧版仅支持 City 1.0 的客户端不能直接读取 1.1，需使用新版解析器。
- 此 JSON 扩展尚无原 C++ GUGIS 二进制兼容实现。

## 指标与实测

完整起始城市有 139,429 个构件实例，25,058 份局部模板绑定，8,984 个被构件使用的几何原型，平均每原型引用 15.5 次。原型包括参数化单位盒，尺寸另存，因此不等于 8,984 种尺寸完全相同的具体形状。包括远景简模在内的几何库共 10,182 条记录。

文件存储对比使用同一项目的共享 City 1.1 和展开 City 1.0 的紧凑 UTF-8 JSON 字节数，不与逐构件重复网格或 ZIP 比较。当前约 43.07 MB → 33.19 MB，节省约 23.0%。全部楼栋、构件、颜色、节点与道路保持一致；剩余空间仍保存各构件独立的位置和语义关系。后续扩建时指标自动更新。

离线转换并校验后输出，保留输入文件：

```powershell
./.venv/Scripts/python.exe data-pipeline/pack_city.py old-city.gugis.json shared-city.gugis.json
```

接口 `/city/current` 和 `/city/validate` 返回共享 `document` 及 `storage`；保存请求接受 1.0 / 1.1。`revision` 总是当前磁盘字节的哈希，读取旧项目不会悄悄改写磁盘。`storage` 为 1.1 存储指标，旧文件的实际迁移发生在下一次保存。

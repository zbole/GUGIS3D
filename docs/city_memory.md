# 城市数据内存对比

针对当前 615 栋建筑、139,429 个构件的布里斯托城市，在相同 JavaScript 嵌套数组表示下，相比每个构件独立保存点和边，**共享方案的保留数据内存减少约 81.98%**。

这是使用应用真实 `decodeCity` 解码器、在独立 Node.js / V8 进程中测得的城市数据内存，**不是浏览器进程总 RAM 或显存节省率**。此前 23.0% 指 City 1.1 相对 City 1.0 的 JSON 文件存储节省，两者分母不同。

## 实测结果

环境：Windows x64，Node.js v24.13.0。每种方案启动 3 个全新进程，取中位数；单位 MB = 1,000,000 字节。

| 表示方案 | 保留数据内存 | 共享方案相对它节省 |
|---|---:|---:|
| 当前共享几何＋模板实例＋语义结构 | 120.991648 MB | — |
| 全部构件独立点＋边（线框） | 671.252736 MB | **81.98%** |
| 全部构件独立点＋三角面（标准索引网格） | 736.972104 MB | **83.58%** |
| 全部构件独立点＋边＋三角面 | 1,085.106328 MB | **88.85%** |

点线方案节省的绝对值为 **550.261088 MB**，计算公式为：

```text
节省率 = (1 − 共享方案内存 ÷ 对照方案内存) × 100%
       = (1 − 120,991,648 ÷ 671,252,736) × 100%
       = 81.97524695%
```

三次测量中，点线方案最小值为 671.230736 MB，最大值为 671.252952 MB。该波动不影响约 82.0% 的结论。不同运行时、版本与对象布局可能得到不同数值。

## 对照条件

所有方案保留相同的建筑实例、完整构件、分类颜色、语义归属、地理定位、道路、来源信息以及远景简模。即使当前网页只显示部分建筑，测试仍加载整座城市的数据。

- 当前方案直接调用应用的 `decodeCity`，因此组合盒体已展开成应用实际使用的网格，共享网格数组按应用逻辑复用。没有把更小的压缩文件大小冒充已加载内存。
- 对照方案取消跨构件、跨楼栋的几何复用，每个构件拥有独立顶点和索引数组。每条边通过两个索引引用本构件的顶点，不重复保存两个端点坐标。
- 标准盒体使用 8 个点、12 条边。复杂网格去除共面的三角剖分对角线，保留边界与折边；相邻法线点积容差为 1e-12。该处理只用于对照线框，不改变城市文件。
- 独立构件的局部平移和旋转烘焙到其顶点，建筑仍按原实例经纬度定位。城市共同的道路和来源保持一致。
- 纯点线方案不包含表面，不能代替当前实体模型的全部功能；点＋三角面是保留封闭表面的、更直接的索引网格对照。点＋边＋面方案额外显式保存边表，开销更高。

测试读入文件并构造数据后，让解码与转换函数返回，清除源对象和临时缓存的栈引用，再执行三次强制垃圾回收。记录 `heapUsed + arrayBuffers`，减去该进程加载城市之前的对应值。数据对象在采样时保持可访问。

不计入：Cesium 渲染对象、GPU 顶点缓冲和纹理、DOM、页面布局、撤销历史、临时 JSON 字符串、解码峰值及整个浏览器进程的其他开销。不能把本结果写成“浏览器总内存已降低 82%”。

## 固定字宽数值缓冲区估算

下面是独立的几何数值容量估算，用于避免 JavaScript 对象布局影响：坐标、尺寸及变换为 Float64；索引及引用为 Uint32；颜色为 4 字节 RGBA。保留尺寸、构件变换和模板引用开销；不计字符串、对象头、共同地理字段及语义树。当前应用仍使用 JavaScript 数组，这些数字不代表已实现 TypedArray 存储后的实际进程内存。

| 方案 | 数值容量 |
|---|---:|
| 当前共享表达的数值载荷 | 19.220972 MB |
| 独立点＋边 | 122.747828 MB |
| 独立点＋三角面 | 143.081908 MB |
| 独立点＋边＋三角面 | 183.816068 MB |

展开后共有 3,393,798 个顶点、5,091,770 条边；保留三角面时共有 5,089,020 个面，包含远景简模。共享表达实际保留 330,650 个网格顶点、495,984 个三角面，以及盒体尺寸、位置、旋转、颜色和引用参数。

因此，点线方案是否采用扁平 TypedArray、是否跨构件合并重合顶点、是否量化坐标，都会改变分母。本次约 82% 的实测结论限定于上述同类 JavaScript 数组的公平对照，不能推广为所有点线实现的固定节省率。

## 复现

网站底部的“城市数据内存对比”直接展示节省比例与两种方案内存，展开可查看三角网对照和测量口径。网页读取 `shared/city-memory-benchmark.json` 的实测记录，并与当前城市的保存版本核对；项目变更后标记为“上次测量”，不冒充实时结果。页面不再展示旧格式的文件节省百分比。

在仓库根目录运行：

```powershell
node --experimental-strip-types frontend/scripts/city-memory.mjs --input .local/city/current.gugis.json --output .local/city-memory-benchmark.json --runs 3
```

脚本自动在独立子进程中启用垃圾回收测量，并保存每次样本、统计口径与输入哈希。测量过程中不修改城市，也不把对照文件导入编辑器。

需要更新网页展示时，把上面命令的输出路径改为 `--output shared/city-memory-benchmark.json`，测量成功后刷新网页；生产构建需重新执行 `npm run build --prefix frontend`。

输入 SHA-256：`485f64f1bd5e8e2e74a3d4a7ba4b5f6529797d2ddc40ac55b5ca9cc2c0555701`。使用其他城市或后续编辑版本时，必须重新计算。

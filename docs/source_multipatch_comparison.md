# 真实源地形与 ArcGIS 兼容 MultiPatch 的同几何对照

在 /compare#source-function-results 查看“同一三角几何”结果。全部十城二十固定样区的实际文件如下：

| 表示 | 每样区完整文件 |
| --- | ---: |
| GUGIS P1 共享 XYZ、原生三角带，GPR4 | 135,528 B |
| MultiPatch SHP/SHX/DBF/PRJ/CPG | 201,038 B |

相同 P1 表面下，原生文件小 **32.6%**。二十样区合计为 2,710,560 / 4,020,760 B，节省 1,310,200 B。基线按 [Esri Shapefile 规范](https://www.esri.com/library/whitepapers/pdfs/shapefile.pdf)省略可选 M 坐标数组，使用一个要素和 64 个 Triangle Strip 部件；没有用不需要的测量数组或大量属性记录增加基线代价。

每样区 8,192 个三角形对应原始 1 m DTM 的同一 P1 高程函数。原生行三角带与输出列三角带的三角几何集合完全相同，所有原始 XYZ 值保持；输出每个面朝上，无重复、退化或多余补面。共享点的 GUGIS 文件保存 4,225 个节点；MultiPatch 部件保存 8,320 个 XYZ 条目。

独立 PyShp 3.1.6 读取实际 SHP/SHX/DBF，逐一核验全部 163,840 个源三角面、4,096 m² 单样区面积、Z 高程、要素身份、索引偏移和记录长度。发布前重新导出每个五文件包，逐字节一致；实际 ZIP 的五个成员与独立组件也逐字节一致。全部源高程参考格、原生 P1/面带文件、CSV、脚本和科学 SVG 同时提供，报告与 ZIP 绑定 SHA-256。

GUGIS 双线性面带与原生 P1 文件都是 135,528 B；面带保留源单元内部函数，P1 只保留三角平面。这一性质在同源函数试验中独立验证，不将两种不同函数说成相同几何。

这是本项目生成和读回的 ArcGIS 兼容格式对照，尚未在 ArcGIS Pro 中运行软件测试，不证明加载时间、帧率、内存或最优编码。规则 Float32 高程格与无损 GeoTIFF 在这些样区中更小，仍直接展示。XY 为英国国家格网；PRJ 只记录水平坐标系，ODN/米制约定与源 WCS 单位警告保存在源身份回执中。

新增六项导出与发布检查通过，包含损坏 Z、损坏索引的拒绝、全部面集合、完整边界框、原生文件和完整 ZIP；源函数与页面流程八项相关检查通过，TypeScript 检查通过。科学 SVG 在白色背景渲染并检查；真实浏览器验收和 GitHub 上传仍受当前环境的浏览器内核与网络权限限制。

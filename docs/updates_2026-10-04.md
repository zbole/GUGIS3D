## 从哪里进入

打开 [城市选择页](http://127.0.0.1:5173/)，单选或多选城市，然后进入工作区。多选表示可切换的城市集合，同时仅加载一个城市场景。

- 完整编辑：[伦敦工作区](http://127.0.0.1:5173/?city=london)。可编辑建筑、道路、地形与地物，并使用草稿确认和版本恢复。
- 轻量浏览：[伦敦均衡配置](http://127.0.0.1:5173/?city=london&view_mode=tiles)。仅请求已生成缓存中的建筑分块，不先读取整个城市档案。
- 低资源浏览：[伦敦 Economy 配置](http://127.0.0.1:5173/?city=london&view_mode=tiles&tile_profile=economy)。适合希望减少同时载入范围与请求数的演示。

将链接中的 `city` 换为 `bristol` 或 `birmingham` 可进入其他城市。均衡配置为默认值；入口也可直接选择两种配置。

## 本次主要变化

| 功能 | 具体行为 |
|---|---|
| 城市入口 | 进入前选择城市；切换时释放旧场景和读取任务，避免三城同时占用渲染资源 |
| 分块浏览 | 根据视域读取建筑，校验来源修订、字节数与 SHA-256；失败可重试，保留选中建筑 |
| 建筑检索 | 在当前已载入建筑中按名称或 ID 搜索，分页查看位置、几何来源及修订号；主动点击定位才移动相机 |
| 暂停与恢复 | 手动暂停或隐藏页面时停止新的瓦片读取，已验证建筑继续可见；恢复后按最新视域继续 |
| 视角链接 | 复制当前城市、来源修订和相机位置；修订不匹配时明确提示，并可选择当前默认视角 |
| 候选数据审阅 | 对照原始种子与修正候选，下载档案、清单或 ZIP；不自动导入，不自动创建草稿 |
| 英国接入进度 | 展示 76 个城市名单以及样本、边界回执状态，支持地区、名称和状态筛选 |

默认分块相机已按实际缓存范围居中，修复部分横屏尺寸看向样区以外的问题。加载优先级变化而驻留瓦片不变时，复用已有场景与请求，减少重复计算。

| 读取预算 | Balanced 均衡 | Economy 低资源 |
|---|---:|---:|
| 驻留瓦片 / 源字节 | 8 / 8 MiB | 2 / 2 MiB |
| 缓存瓦片 / 源字节 | 16 / 16 MiB | 4 / 4 MiB |
| 同时请求 | 3 | 1 |

这些是源数据载荷和请求调度上限，不能作为实测 JavaScript 内存、GPU 显存或帧率提升。完整编辑模式仍加载完整档案；分块浏览不包含道路、地形、函数地物和完整语义，也没有保存或修改接口。

## 数据范围与本地项目

三个城市仍是局部街区样本：仓库布里斯托种子 615 栋、伦敦 823 栋、伯明翰 809 栋，不能代表全城覆盖。76 城名单用于记录后续接入准备，不表示取得了 76 城模型或边界，不能据此计算覆盖率。高度标签未独立核验，多数建筑高度为推算或显示假设；没有新增实测 DEM。

伦敦修正候选为 814 栋，伯明翰为 804 栋：保留可解析的来源高度，明确遗漏当前不支持的建筑部件及底部高度语义。候选与现有项目分开保存，**不会自动激活**。候选是整城替换档案，不是只修正高度的补丁；手动提交替换可能移除候选中没有的用户对象，应先导出并审阅草稿。

本机布里斯托正式项目仍为 **616 栋，保留 40 个历史版本**。它启用了建筑贴地，当前 render-package v1 不支持该偏移，构建器会明确拒绝。本次布里斯托只读缓存单独由仓库 **615 栋种子**生成，因此与完整编辑项目并非同一修订，也不包含本机新增建筑及正式地形。伦敦和伯明翰缓存由各自原正式项目生成，保留 823 / 809 栋来源状态。页面的已载入数量是视域内子集，应与源档案总量区分。

`X-Render-Freshness: current` 仅表示正式项目或种子与构建时记录的文件签名一致。`unknown` 表示未能以该签名确认一致，不等于内容已经过时，也不证明与当前项目相同。编辑保存不会自动重建缓存；视角链接中的修订号也不能用于自动取回历史数据。

## 明确选择缓存来源

在仓库根目录使用已有 Python 环境。下面两组是不同来源选项，不需要依次运行；均只写 `.local/render-cache`，不修改输入档案。

重现仓库种子的三城缓存：

```powershell

.\.venv\Scripts\python.exe data-pipeline/build_render_tiles.py backend/data/cities/london.gugis.json --city london
.\.venv\Scripts\python.exe data-pipeline/build_render_tiles.py backend/data/cities/birmingham.gugis.json --city birmingham
```

本次本机演示使用的来源：布里斯托选仓库种子；另两城选本机正式项目。

```powershell
.\.venv\Scripts\python.exe data-pipeline/build_render_tiles.py backend/data/bristol.gugis.json --city bristol
.\.venv\Scripts\python.exe data-pipeline/build_render_tiles.py .local/cities/london/current.gugis.json --city london
.\.venv\Scripts\python.exe data-pipeline/build_render_tiles.py .local/cities/birmingham/current.gugis.json --city birmingham
node frontend/scripts/verify-render-streaming.mjs
```

普通、不启用贴地的布里斯托正式项目可明确选择 `.local/city/current.gugis.json` 作为输入；本机现有 616 栋贴地项目应保留原状，不能为生成缓存而关闭贴地或用种子覆盖。当前缓存不能自动修正建筑高度或补上缺失层。缺少缓存时页面给出构建与重试提示，不悄悄改为全城下载。

`.local` 中的正式项目、草稿、历史、渲染缓存和验收日志均不上传 GitHub。源数据与种子按仓库既有许可公开；新电脑需要自行构建缓存。英国边界回执的安全文件读写当前需要 POSIX 支持，Windows 上显示未核验属于平台限制；城市编辑和分块浏览仍可使用。

## ArcGIS 报告导入顺序与保留状态

- 连续选择报告时仅最新一次读取可以更新展示和缓存；较早读取迟到或失败，不覆盖最新报告，也不打断它的加载提示。
